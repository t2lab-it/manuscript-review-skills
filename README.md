# manuscript-review-skills

研究内容を保ったまま文章を点検し、著者が根拠と理由を理解して自分で原稿を直せるようにするためのスキルです。
指摘・局所的な修正案または著者への質問を応答として返し、採否と原稿への反映は利用者が行います。

## スキルを選ぶ

| 対象 | スキル | 詳しい使い方 |
|---|---|---|
| 日本語の研究原稿 | [check-japanese-manuscript](skills/check-japanese-manuscript/SKILL.md) | [USAGE.md](skills/check-japanese-manuscript/USAGE.md) |
| 英語の論文原稿（学会論文を含む） | [check-english-manuscript](skills/check-english-manuscript/SKILL.md) | [USAGE.md](skills/check-english-manuscript/USAGE.md) |
| 英語の研究発表用読み上げ原稿 | [check-english-presentation-script](skills/check-english-presentation-script/SKILL.md) | [USAGE.md](skills/check-english-presentation-script/USAGE.md) |

どのスキルも原稿・参照ファイルを直接編集しません。
研究内容の更新、科学的正しさの審査、数式・構文・組版の修復やビルドは対象外です。
英語の2スキルは翻訳・新規執筆を扱わず、説明は日本語、引用と英文案は英語が既定です。

## 共通の使い方

1. 対象に合うスキルを選び、原稿の本文または読取り可能なファイルを渡します。一部だけなら対象範囲を指定し、参考資料と添削対象を区別します。
2. 指摘の根拠・理由と修正案、または不足情報への質問を確認します。数値・否定・条件・主張の強さ等の意味が保たれるか確認し、自分で原稿へ反映します。
3. 前回の指摘と修正後の該当箇所を渡すと、問題が解消したか再確認できます。提示案との文字列一致ではなく、問題の解消で判断します。

### スキル対応環境で使う

利用環境の手順に従って、選んだ `skills/<スキル名>/` フォルダを登録または指定します。
`SKILL.md` を入口とし、同じフォルダの `references/` も読み取れるようにしてください。
呼出し名を使える環境では `$check-japanese-manuscript` 等で指定できます。
各フォルダは独立して使え、他スキル・元の添削履歴・教員用資料は不要です。

### 通常のチャットで使う

選んだスキルの `SKILL.md` と点検したい原稿を添付または貼り付けます。
全体点検でも、まず `SKILL.md` 内の全原則を使えます。
判断に迷う箇所や説明例が必要な場合だけ、該当する `references/` の本文も渡してください。
リンクだけで本文が渡るとは限らないため、AIが実際に読めた範囲を確認します。

ローカルLLMにも同じMarkdownを渡せますが、読込み可能であることと添削性能は別です。
特定の環境・モデルで検証済みという意味ではありません。
原稿の分割、Typst／LaTeXソース、別の対話での再確認は各スキルの `USAGE.md` を参照してください。

## 日本語研究原稿の点検

論旨や説明を読者が追えるかを点検します。英語校閲は対象外です。

> このスキルを使って、原稿の「方法」節の日本語を点検してください。
> 読めた範囲を示し、理由と修正案または著者への確認を返してください。
> 原稿や参照ファイルには書き込まないでください。

## 英語論文原稿の点検

論文の本文・見出し・図表キャプション・付録を点検します。読み上げ原稿は別スキルで扱います。
必要な図表や定義があれば併せて渡せますが、未提供でも本文の点検は進められます。

> この論文のMethodsの英文を点検してください。
> 説明は日本語、修正案は英語で、読めた範囲と未確認事項を示してください。
> 原稿や参照ファイルには書き込まないでください。

## 英語の研究発表用原稿の点検

読み上げ原稿を文章として点検します。図・スライド・音声は不要です。
スライドとの照合、発音・話速・発表時間は対象外です。

> この英語の読み上げ原稿を文章として添削してください。
> 理由は日本語、英文案は英語で示してください。
> 原稿を直接編集せず、研究情報が必要な箇所は具体的に質問してください。

## 構成と責務

| ファイル | 責務 |
|---|---|
| `README.md` | スキルの選択と共通の利用手順 |
| 各スキルの `SKILL.md` | 対象、操作境界、意味保持、全原則の判断基準、指摘と再確認の契約 |
| 各スキルの `USAGE.md` | 利用者向けの入力例、環境ごとの渡し方、分割・再確認の手順 |
| 各スキルの `references/` | 必要時に読む、原則ごとの詳しい適用条件・例外・別題材の例 |

データは「原稿・著者補足 → スキルによる点検 → 指摘・理由・案または質問 → 利用者による修正 → 再確認」と流れます。
原稿は読取り対象で、再確認の記録は対話内、または利用者が保管する前回の指摘です。
リポジトリは原稿や添削履歴を保存せず、実行プログラム・生成処理・外部サービスへの依存も持ちません。

点検の完了は、依頼範囲と実際に読んだ範囲を区別し、根拠のある指摘または問題を検出しなかった旨を返し、未確認資料・未解決の質問を明示することです。
再確認では指摘ごとに「解消・一部解消・未解消・判断材料不足」を返します。
未読部分や科学的正しさまで保証したり、指摘をゼロにするために意味を変えたりしません。

保守では、単独のフォルダで使えること、原則IDと参照パス、意味保持・非編集・範囲報告・再確認の契約を維持します。
共通処理のための別スキルや生成層は設けず、各スキルの判断基準はその `SKILL.md` で管理します。
参照資料は例としての役割があるため、短さだけを理由に削除せず、判断に寄与するかを確認します。
