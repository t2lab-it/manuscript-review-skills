# 原稿の渡し方と再確認

このフォルダと英語の読み上げ原稿の本文を用意します。
説明は日本語、引用と英文案は英語が既定です。
案の採否を決め、自分で原稿へ反映します。

## 最初の依頼

本文を貼り付けるか、読取り可能なファイルを指定します。
一部だけを点検する場合は、対象の節・ページ・段落を示します。
聴衆や綴りの方針が決まっていれば添えます。

> この英語の読み上げ原稿を文章として添削してください。
> 理由は日本語、英文案は英語で示し、研究情報が必要な箇所は具体的に質問してください。

## 環境ごとの渡し方

スキル対応環境では、このフォルダ全体を読めるようにして `SKILL.md` を指定します。
名前で呼び出せる環境では `$check-english-presentation-script` を使えます。
配置・登録は利用環境の手順に従います。

通常のチャットやローカルLLMには、`SKILL.md` と原稿の本文を渡します。
説明例が必要なときに、`references/judgment-examples.md` の本文を追加します。
受領した本文と参照資料の範囲をAIに示してもらいます。

長い原稿は節単位で分け、必要な前後の定義、指摘一覧、点検済みの箇所と残りを引き継ぎます。
Typst／LaTeXソースも文章を点検対象とし、数式・ラベル・引用・参照・includeは原文を保持します。

## 採用と再確認

案の根拠と、数値・否定・条件・主張の強さ等の意味保持を確認して採用します。
質問には著者が確定した情報で答えます。

> 前回指摘と修正後の該当箇所を渡します。
> 指摘ごとに解消・一部解消・未解消・判断材料不足を、理由とともに示してください。
> 新しい意味変更は前回の問題と分けて示してください。

別の対話では、前回指摘の理由と修正後本文を渡します。
比較に必要な修正前本文や関連文脈も添えます。
